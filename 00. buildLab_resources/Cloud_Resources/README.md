# Cloud engineering track

## Mission

Deploy the shared product with a clear security boundary, repeatable infrastructure, observable runtime, and controlled cost. Cloud is an application delivery concern shared with DevOps and backend—not a separate destination after coding.

## Six-month progression

| Month | Learn and practice | Product deliverable | Validation |
| --- | --- | --- | --- |
| 1 — Cloud foundations | Regions, identity, networking, storage, compute, shared responsibility, cost | Architecture vocabulary and request-path diagram | Explain where data travels and who can access it |
| 2 — Choose an environment | AWS or Azure fundamentals, managed services, secrets, database hosting | Service comparison and decision record | Security, availability, and cost trade-offs reviewed |
| 3 — First deployment | Container/runtime deployment, DNS, environment configuration, database migration | Development/staging deployment | Rebuild and redeploy from written steps |
| 4 — Reliability | Health checks, logs, metrics, backups, scaling, security groups/firewalls | Basic observability and recovery checklist | Simulated failure and recovery evidence |
| 5 — Infrastructure as code | Terraform concepts, CI/CD, policy, drift, safe changes | Versioned infrastructure change in a sandbox | Peer review and plan/apply evidence |
| 6 — Release operations | Cost review, release checklist, rollback, runbook, handoff | Architecture diagram and production-style runbook | Another intern can operate the environment |

## Required outputs

- Cloud architecture diagram.
- Identity and least-privilege plan.
- Environment and secret-management guide.
- Staging deployment and rollback procedure.
- Health, log, backup, and cost checklist.
- Infrastructure-as-code exercise.
- Final runbook and cost estimate.
